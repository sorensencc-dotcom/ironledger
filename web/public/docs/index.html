IronLedger Operator Guide & Reference

IronLedger is an enterprise financial operating system combining plaintext Beancount accounting authority with SQLite analytical projections, compliance Merkle trees, pure rational fraud detection, multi-tenant federation, and lease-fenced event streaming.

Diataxis 1

Quickstart Tutorial: Ingestion, Verification, and Federation

In this 4-step workflow, you ingest source statements, review transactions in the workbench, generate compliance audit bundles, and publish federated event streams.

1 Ingest Statement Records

Stage bank records into the local database from OFX or CSV exports: 

python -m ironledger.cli import inbox/checking_export.ofx --confirm "import inbox/checking_export.ofx"

2 Review and Approve in Operator Workbench

Launch the local Operator Workbench web application to review staged items: 

python -m ironledger.cli web --db ironledger.db --open-browser

Navigate transactions with j / k, trigger categorization rules with Ctrl+R, and approve with a.

3 Generate Sealed Compliance Audit Bundle

Create a tamper-evident RFC 6962 binary Merkle tree bundle for regulatory inspection: 

python -m ironledger.cli compliance generate --framework SOC2_TYPE2 --out audit_bundle.tar

4 Dispatch Federated Events

Deliver pending outbox events across peer cluster nodes using fenced worker leases: 

python -m ironledger.cli federation outbox dispatch --worker-id worker_prod_1 --batch-size 50

How-To Guides

How to Review, Split, and Approve Staged Transactions

Staged transactions require balanced contra account postings before compilation into plaintext Beancount files.

  1. Select any row in the Staging Inbox with status pending.
  2. To split a single transaction across multiple expense categories, supply minor-unit postings summing exactly to 0.
  3. Press a to approve the transaction. Approved entries advance to approved status.

How to Generate and Verify Compliance Audit Bundles

Compliance audit bundles encapsulate canonical JSONL streams for mutation events, governance logs, and pricing history inside deterministic TAR archives.

  1. Generate an audit bundle: 
    python -m ironledger.cli compliance generate --ledger-id default --framework SOC2_TYPE2 --out bundle.tar
  2. Verify bundle integrity and Merkle root correctness: 
    python -m ironledger.cli compliance verify --bundle bundle.tar

How to Detect and Resolve Rational Anomaly Flags

The anomaly detection engine uses exact rational integer arithmetic ($N/D$, zero float division) to identify duplicates, velocity spikes, and statistical outliers.

  1. Scan the ledger for anomalies: 
    python -m ironledger.cli anomaly scan --ledger-id default
  2. List unresolved flags: 
    python -m ironledger.cli anomaly list --status UNRESOLVED
  3. Resolve a detected flag with audit tracking: 
    python -m ironledger.cli anomaly resolve --flag-id flag_123 --status CONFIRMED_FRAUD --actor operator_1

How to Manage Multi-Tenant Cluster Federation

Federated clusters communicate via the gov.event.v1 canonical envelope with lease-fenced outbox delivery.

  1. Inspect registered cluster nodes: 
    python -m ironledger.cli federation nodes list
  2. Check outbox queue depth: 
    python -m ironledger.cli federation outbox list --unpublished-only
  3. Dispatch pending events to peers: 
    python -m ironledger.cli federation outbox dispatch --worker-id worker_primary

How to Operate Connectors, Webhooks, and DLQ Redrive

External connectors use token bucket rate limiting and circuit breakers. Webhook deliveries support HMAC signatures and atomic dead-letter queue redrive.

  • Credential Inspection: Credentials use AES-256-GCM envelope encryption. The UI reports DEK rotation age and fingerprint without leaking plaintext secrets.
  • Dead-Letter Queue Redrive: In the Webhooks Workbench view, click Redrive Delivery on any failed delivery to reset status to PENDING and re-enter the dispatch queue.
  • Circuit Breakers: Breakers automatically transition to OPEN upon consecutive upstream failures, preventing resource exhaustion.

Explanation & System Invariants

Meta-Ledger Cryptographic Chaining

Financial operations enforce an unbroken SHA-256 hash chain in mutation_events. Every compilation write calculates directory hashes before and after mutation, linking records back to genesis. SQLite triggers prevent modifications or deletions.

Canonical gov.event.v1 Event Model

All cross-cluster and internal events follow the canonical gov.event.v1 schema. Timestamps use UTC RFC 3339 format, and event IDs derive deterministically from SHA-256 digests of the canonical payload. EventRouter atomically persists events into both the outbox and governance audit trails.

Fenced Worker Lease Architecture

To prevent double-dispatch in distributed deployments, outbox workers acquire batches with randomized UUID fence tokens (lease_fence_token). When a worker lease expires and another worker claims the batch, stale acknowledgements affect zero rows.

Pure Rational Integer Arithmetic

Floating-point arithmetic is forbidden across all accounting, token bucket, rate limiter, and anomaly detection calculations. All ratios and statistical variance formulas operate on integer fractions ($N/D$), eliminating representation drift.
