IronLedger Operator Guide & Reference

IronLedger is a local-first, single-operator financial operating system. Plaintext Beancount is the sole accounting authority; SQLite is a disposable, rebuildable analytical projection.

Diataxis 1

Quickstart Tutorial: From Import to Plaintext Ledger

In this 3-step tutorial, you will ingest bank export records, categorize and approve them in the Operator Workbench, and compile them into verified Beancount plaintext files.

1 Ingest Bank Statement Files

Run the CLI import pipeline to stage OFX or CSV records into your local staging database: 

python -m ironledger.cli import inbox/checking_export.ofx --confirm "import inbox/checking_export.ofx"

2 Open Operator Workbench

Launch the visual workbench to review staging entries with sub-second keyboard shortcuts: 

python -m ironledger.cli web --db ironledger.db --open-browser

Use j / k to select transactions, Ctrl+R to learn a rule, and a to approve.

3 Simulate and Compile to Beancount

Trigger a safe-mode dry-run simulation first to inspect the unified plaintext diff, then compile directly to disk: 

python -m ironledger.cli compile --ledger-dir ledger --confirm "authorize compile"

How-To Guides

How to Review, Categorize, and Approve Staged Transactions

Staged transactions require matching contra accounts before compilation. To review:

  1. In the Staging Inbox, select any row with status pending.
  2. Inspect the raw source evidence and Beancount syntax in the right Inspector Sidecar.
  3. Press a or click Approve. If uncategorized, enter target account (e.g. Expenses:Food:Groceries).
  4. Approved transactions advance to approved status, ready for compilation.

How to Execute a Multi-Leg Transaction Split

When a single payment covers multiple expenditure categories, split the contra leg:

  1. Select the transaction in the Register Grid.
  2. Call the split API or modal with balanced minor-unit postings: 
    POST /api/staging/{id}/split
{
  "postings": [
    {"account": "Assets:Checking", "currency": "USD", "minor_units": -5000, "scale": 2},
    {"account": "Expenses:Groceries", "currency": "USD", "minor_units": 3500, "scale": 2},
    {"account": "Expenses:Household", "currency": "USD", "minor_units": 1500, "scale": 2}
  ]
}
  3. The system validates that the sum of all postings equals exactly 0 minor units.

How to Operate Under Safe Mode Gating

Safe mode protects against accidental or automated live disk modifications.

  • Dry-Run Simulations: Allowed at all times without confirmation token (POST /api/compile/simulate).
  • Live Compiles: Require passing "safe_mode_token": "authorize compile" in the request payload.
  • Safe Mode Disable: Place {"enabled": false} in config/safe-mode.json for full operator write access.

How to Run IronLedger Automatically via Docker

Run the containerized workbench service with host persistence and auto-restart: 

# Launch in background
docker compose up -d

# Inspect live logs
docker compose logs -f

# Shutdown container
docker compose down

Explanation & System Invariants

Why Meta-Ledger Cryptographic Chaining Matters

Financial systems often suffer from untracked data drift between review databases and final ledger files. IronLedger solves this via an append-only mutation_events table. Every compilation write calculates the SHA-256 digest of the entire on-disk ledger directory before and after writing, linking them into an unbroken cryptographic chain anchored at genesis. SQLite database triggers strictly forbid any UPDATE or DELETE operations.

Hit Confidence Trend (HCT) & Drift Detection

Machine learned categorization rules decay over time as merchant narrations change. IronLedger computes an active Hit Confidence Trend metric:

HCT = max(0.0, 1.0 - (OverrideRate * 1.5) - DecayFactor(t))

Rules with HCT ≥ 80% display in emerald. When override rates rise, rules degrade to amber warnings and are automatically blocked from automated bulk categorization.
